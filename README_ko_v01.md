# Noodoe Probe

KYMCO Noodoe 계기판을 위한 iOS **읽기 전용 진단 도구**입니다. iPhone에서 계기판이 실제로 어떻게 연결되고 통신하는지 확인하는 데 사용합니다.

**이 앱은 명령을 전송하거나 Bluetooth 특성(Characteristic)에 데이터를 쓰지 않습니다.** 장치 검색, 읽기 및 로그 기록만 수행합니다.

## 주요 기능

- **액세서리(ExternalAccessory / iAP2):** 연결된 액세서리의 이름, 제조사, 모델, 일련번호, 펌웨어 및 하드웨어 버전, `protocolStrings`를 표시합니다. `sunray.control` / `sunray.data` 채널을 대상으로 송신 없이 수신만 하는 수동 모니터링을 지원하며, 수신 데이터는 16진수로 기록합니다.
- **BLE:** 장치를 검색하고(이름 필터 선택 가능, 기본값: `Noodoe`), 광고 데이터(Solicited Service UUID 포함)를 표시합니다. 연결 후 모든 서비스와 특성을 탐색하고, 특성 값을 읽거나 알림을 구독할 수 있습니다. Device Information은 자동으로 읽고 해석하며, PnP ID에 포함된 제조사 ID도 확인합니다. **시스템에 연결된 BLE 장치 찾기** 기능을 사용하면 iOS가 ANCS 용도로 이미 연결하여 더 이상 광고하지 않는 장치도 찾을 수 있습니다.
- **로그:** 모든 이벤트에 타임스탬프를 기록하며 복사하거나 공유할 수 있습니다. 로그는 앱의 Documents 폴더에도 저장되어 iOS 파일 앱에서 `probe-*.log` 파일로 확인할 수 있습니다.

## 서명되지 않은 IPA 받기(GitHub Actions)

1. GitHub에서 새 저장소를 만들고 `.github` 폴더를 포함한 이 폴더의 모든 내용을 푸시합니다.
2. `main` 브랜치에 푸시하면 GitHub Actions의 **Build unsigned IPA** 작업이 자동으로 실행됩니다. Actions 탭에서 `workflow_dispatch`로 수동 실행할 수도 있습니다.
3. 작업이 완료되면 실행 결과 페이지 하단의 **Artifacts**에서 `NoodoeProbe-unsigned-ipa`를 다운로드합니다. 압축을 해제하면 `NoodoeProbe-unsigned.ipa` 파일이 나옵니다.
4. `v1.0`과 같은 태그를 푸시하면 IPA가 GitHub Releases에도 첨부됩니다.
5. 평소 사용하는 사이드로딩 도구로 IPA에 서명하고 설치합니다.

## 권장 테스트 절차(순정 펌웨어)

1. 동일한 연결을 두고 충돌하지 않도록 공식 Noodoe 앱을 **완전히 종료**합니다(앱 전환 화면에서 위로 쓸어 닫기).
2. iPhone의 **설정 > Bluetooth**에서 `KYMCO Noodoe`와 페어링하고 연결합니다.
3. Noodoe Probe를 실행한 뒤 **액세서리(Accessories)** 탭에서 계기판과 프로토콜 문자열이 표시되는지 확인합니다. 필요하면 수동 모니터링을 시작합니다.
4. **BLE** 탭에서 **시스템에 연결된 BLE 장치 찾기**를 선택하거나 `Noodoe ANCS`를 검색합니다. 연결한 뒤 서비스를 확인합니다. Device Information의 PnP ID와 버전 문자열은 자동으로 읽습니다.
5. 테스트가 끝나면 **반드시 연결 해제(Disconnect)를 누르세요.** 그래야 iOS가 ANCS 연결을 다시 사용할 수 있습니다. 그렇지 않으면 계기판에서 알림을 일시적으로 받지 못할 수 있습니다.
6. **로그(Logs)** 탭에서 로그 파일을 공유합니다. 공유하기 전에 일련번호나 장치 주소 등 공개하고 싶지 않은 정보가 포함되어 있는지 확인하세요.

## 알려진 제한 사항

- ExternalAccessory는 앱의 `Info.plist`에 선언된 **프로토콜 문자열을 지원하는 액세서리만** 표시합니다. 현재 `sunray.control`과 `sunray.data`를 선언하고 있으며, 이는 공식 Noodoe 앱 버전 2.2.1에서 확인한 값입니다. 액세서리가 보이지 않는다면 프로토콜 문자열이 다를 수 있습니다.
- 계기판은 휴대전화가 먼저 핸드셰이크 명령을 보내야 응답할 수 있습니다. 따라서 수동 모니터링만으로는 데이터를 수신하지 못할 수도 있습니다.
- **읽을 수 있는 모든 특성 읽기** 기능을 사용할 때 암호화가 필요한 특성을 만나면 iOS에 페어링 요청이 표시될 수 있습니다. 해당 요청은 거절하세요.
- 이 프로젝트는 Swift 컴파일러가 없는 환경에서 작성되었으며 **아직 컴파일 검증을 거치지 않았습니다**. 첫 빌드에 실패하면 문제를 수정할 수 있도록 GitHub Actions 오류 로그를 공유해 주세요.
